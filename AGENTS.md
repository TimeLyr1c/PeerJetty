# Project rules

Read Docs/development-plan.md and README.md before changing behavior. Preserve the Original source baseline. Never use SSH. Received files stay unopened by default; the user explicitly authorized an optional auto-open switch on 2026-10-05. Only open committed, fully received roots when this local setting is enabled, never partial/failed/cancelled transfers. Credentials, certificates with private keys, device trust records, actual transfers and build outputs must stay out of Git.

Use system TLS and CryptoKit; changes to pairing require adversarial tests. Validate paths before writing and never overwrite existing received files. A transfer succeeds only after receiver integrity checks and final commit. Keep smoke tests isolated from production Keychain/configuration and explain real-device coverage honestly.

SwiftPM owns build/test configuration. Install the app at a stable Applications path after verification. Update each computer's management archive only with that computer's verified state. The project owner reports that they and the Starter author agreed to MIT licensing; the root LICENSE and LICENSE-NOTES.md record that decision. Preserve Original unchanged. The current icon was supplied and authorized by the project owner. Legacy icon artwork has been excluded from public history and retained only in ignored local files/private backups; do not re-add it without verified redistribution terms; do not treat a source license agreement as third-party artwork permission.

Save completed, verified work as a focused local Git commit before finishing a coding task. Check existing changes first; never include unrelated user edits. Record the commit ID and any remaining uncommitted work in the final response. For incomplete work, checkpoint at meaningful milestones and clearly label WIP. Local commits do not authorize pushing to a remote. Keep the established Bundle ID, Keychain service and protocol-v1 identifiers stable unless implementing and testing an explicit compatibility migration.

Public documentation: keep README.md (English) and README.zh-CN.md aligned and write release notes in English and Simplified Chinese. Upload only the DMG installer as a release asset; keep ZIP, checksums and build/signature records in local ignored archives. Do not move existing release tags or rebuild published binaries for documentation edits. App UI localization is separate from documentation translation.

Delivery cadence agreed on 2026-10-06: commit meaningful verified changes frequently, but do not bump product versions or package each small fix/feature. Ordinary builds retain the current version. Batch changes for device testing; increase build numbers for distinct test installers under the same planned product version. Publish one accepted build per public product version, and increase the product version for subsequent public updates. Never overwrite old archives, rebuild published binaries or move existing tags.


## UI and design

PeerJetty is Swift/AppKit + Auto Layout + Core Animation, built with SwiftPM. Keep Apple HIG and native macOS interactions first. Before UI work read [design rules](Docs/design/DESIGN_SYSTEM.md), then the relevant [component inventory](Docs/design/COMPONENTS.md) or [motion rules](Docs/design/MOTION.md). Existing feature specifications remain authoritative for behavior; do not silently turn a visual experiment into a product-wide standard.

- Reuse existing components and native AppKit controls before adding custom ones. SwiftUI is an option for a justified future surface, not a reason to rewrite working AppKit. Custom components are for PeerJetty-specific interactions or unmet platform needs. Keep appearance, interaction and feedback consistent across windows.
- HeroUI is a component/interaction reference here; Motion (the JavaScript library) is an animation reference, distinct from our native Motion.swift. Do not add React, a webview, Node runtime, or either library to this native app to follow a reference. If a separately approved web surface is introduced, first check HeroUI's existing components and current framework compatibility.
- Design language: minimal, native, restrained, modern, calm, precise. Prioritize information hierarchy → space/layout → type/readability → state feedback → motion → decoration. Express paired devices, connection, ready/sending/receiving/completed/failed states and transfer direction clearly.
- Use semantic system colors, system typography, SF Symbols, Auto Layout and native focus/keyboard behavior. Sync English/Chinese UI text; preserve user content verbatim. Do not rely on color, tooltip, truncation or motion alone for essential information.
- Avoid excessive gradients/glow/glass, oversized rounded cards, decorative animation, landing-page layouts and generic dashboard styling. Glass stays confined to the existing drop card with the macOS 15 fallback; text bodies remain opaque. Use public accessibility APIs, never private transparency preferences.

## Motion

- Use native implicit/simple transitions for hover, color and opacity. Use the existing MotionPolicy/MotionProfile/MotionEffects/WindowMotion and Core Animation for complex states, enter/exit, layout, springs and gesture feedback; don't build another animation subsystem.
- Motion must explain state, spatial relationships or action feedback. Ordinary new effects should usually be 150–300 ms and restrained; springs are tuned to the interaction. Existing explicitly approved speed profiles and completion sequences are documented exceptions, not defaults for new controls. Do not shorten those sequences as part of unrelated cleanup.
- Respect the local animation toggle and system Reduce Motion; Reduce Transparency/Increase Contrast suppress optional trails. Final state, focus, hit targets, transfer progress, confirmation and cancellation must work without animation. Visual progress may lag real progress, never lead it; success needs receiver confirmation.
- Use finite, keyed effects. Capture speed per effect, retarget from current presentation/velocity where appropriate, invalidate stale callbacks by revision/transfer ID, and stop effects when hidden or superseded. Hide windows before restoring alpha. Do not add decorative loops, particles, frame loops or animation polling.
- Validate relevant states and interruption paths, both languages, light/dark, small windows, long names, accessibility and fixed drag targets. Use existing isolated UI/motion checks; record real Air/mini coverage honestly. Preview artifacts stay ignored. Update the design inventory when adding a reusable component; update motion specifications when changing timing/curves.
