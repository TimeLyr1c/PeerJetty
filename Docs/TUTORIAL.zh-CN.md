# PeerJetty 使用教程

[English](TUTORIAL.md) · **简体中文** · [项目首页](../README.zh-CN.md)

本教程以 **0.4.0 开发版源码**为准，当前公开 DMG 仍是 **0.3.2**。安装、文件传输和配对基础步骤通用；这里的五页设置、文本历史、独立图标开关、启动重连和改进的失败处理属于 0.4.0。测试时建议两台使用同一当前构建。本地安装包可能未包含之后只在源码完成的修复，详见[验证记录](VALIDATION.md)。

## 安装

准备两台运行 macOS 15 或更新系统的 Apple Silicon Mac，保持唤醒并连接同一局域网，两端都运行 PeerJetty。直接传输不需要互联网；下载安装包和检查 GitHub 更新需要联网。

1. 在每台 Mac 上，从 [Releases](https://github.com/TimeLyr1c/PeerJetty/releases/latest) 的 **Assets** 下载 DMG，或使用维护者提供的测试 DMG。
2. 打开镜像，把 `PeerJetty.app` 拖入 **Applications（应用程序）**。运行安装后的副本，不在镜像内运行；然后推出镜像。
3. 打开 PeerJetty。新安装默认显示菜单栏图标、不显示 Dock 图标，从菜单选择“设置…”。
4. 在“通用”输入便于识别的本机名称，点击“保存”；在“传输”选择接收目录。两台电脑分别保存自己的设置。
5. 系统询问时允许局域网访问。通知方便查看收件，但关闭通知不影响文件传输；保存文件需要相应的目录权限。

当前安装包采用 ad hoc 签名，未经过 Apple 公证。如果系统无法验证开发者或检查应用，请先确认安装包来自本仓库。在确认来源可信且系统提供该入口时，尝试打开一次，再到“系统设置 → 隐私与安全性 → 仍要打开”。“检测到恶意软件”或“应用已损坏”需另行排查。参照 [Apple 官方说明](https://support.apple.com/en-us/102445)。

0.4.0 中若两个图标都隐藏了，从 Applications 或 Spotlight 重新打开 PeerJetty，可恢复设置及临时菜单栏入口，详见[图标开关](#图标开关)。

## 配对两台 Mac

1. 在两台电脑上打开“设置 → 设备”。
2. 两端都点击“添加设备 · 2 分钟”，在两分钟配对窗口内操作。菜单里的“配对…”也会在本机开启窗口，但不会自动批准对方。
3. 选中另一台 Mac，点击“连接 / 配对”。
4. 核对两台屏幕的六位校验码，仅在完全一致时双方确认；不同则取消。
5. 选择已配对设备作为默认文件发送目标。每台电脑分别选择自己的目标。

配对会保存信任，下次不必重复核对验证码，但不代表对方应用当前运行。0.4.0 的“已配对 · 已连接”表示存在可用的认证连接；“已配对 · 未连接”表示信任仍在，但当前没有可用连接。

0.4.0 通用页的“启动时自动连接上次设备”默认开启。成功连接过一次后，启动发现该可信设备时可尝试重连。它和默认文件目标分开，不会唤醒对方，也不会自动发送内容。首次升级后需要成功连接一次，才能建立这条记录。

## 发送与接收文件

### 拖入卡片

1. 在设备页确认默认目标。
2. 将文件或文件夹拖向**菜单栏下方、屏幕上方中央**。
3. 卡片出现后拖进实体卡片，再松开。无需碰屏幕最上沿，那里可能触发 macOS 调度中心。
4. 查看目标名称和传输状态。“对方已保存”表示接收端已校验并保存，不只是字节传完。

没有刘海的显示器也使用同一操作。0.4.0 传输时可点击卡片右侧 **×** 取消对应任务，任务结束后叉号消失。多个任务重叠时，卡片优先显示最近开始且仍活动的任务。

### 使用文件选择器

从菜单选择发送文件，或使用“设置 → 传输 → 选择文件发送…”。它和拖拽使用同一个默认目标及传输规则。

接收端保存到自己选择的目录。同名项目添加后缀，不覆盖已有内容。可在“传输 → 在 Finder 中显示最近收到的文件”查看本次运行的收件。

“收到后自动打开”默认关闭。若希望可信设备发来的完整文件由默认应用打开，可在接收端开启；文件夹在 Finder 打开。它不影响文本，也不会打开部分失败的传输。

两台可以同时互发。支持多个请求，但每条连接同时处理一个发送任务和一个接收任务，额外发送请求排队。没有离线投递队列；连接或传输失败后需主动重试，不支持断点续传。

### 对方未连接或空间不足

当前 0.4.0 源码向已发现但未连接的目标发送文件时，最多尝试连接五秒。失败后卡片和设置说明原因；请在同一局域网打开对方应用，再重新发送。失败请求不会之后自行发出。

磁盘不足时两端显示失败原因。请释放**接收端**空间后重试。多项目任务可能在最终保存途中失败，已经完整保存的项目会保留，提示显示数量；未完成临时内容被清理。再次发送可能生成带后缀的副本。同连接的独立反向传输不会因为一个接收任务磁盘满而被取消。

这项磁盘不足精修目前相对于 build27 仍是仅源码完成的更新，使用本地安装包前请核对[验证记录](VALIDATION.md)。

## 发送纯文本——0.4.0

1. 确认两台都支持文本，目标已经配对且**已连接**。未连接时先在“设置 → 设备 → 连接 / 配对”建立连接。
2. 在菜单栏选择“发送文本…”。
3. 选择目标，手动输入或粘贴纯文本。临时更换文本目标不会修改默认文件目标。
4. 点击“发送”或按 **⌘Enter**；Enter 换行，Esc 关闭面板，输入法正在组词时先正常取消组词。

单条最大 **256 KiB UTF-8**，emoji 可能占多个字节。不能发送空字符串，空格、换行和 Unicode 原文都会保留。

等待确认时保留已提交的草稿；确认收到后清空，失败或三十秒未确认则保留。“未确认收到”表示结果不确定，不代表对方一定没收到，不自动重发。关闭面板在本次运行内保留未发送草稿；退出 App 后丢弃。

接收通知只显示发送设备，不显示正文。点击后查看并选择“复制文本”。通知不可用时，使用“设置 → 文本 → 查看最近收到的文本…”。不自动覆盖剪贴板、执行命令或打开链接；文件自动打开开关不影响文本，也不生成 `.txt` 文件。

## 文本历史与隐私——0.4.0

**成功发送和接收的文本始终在各自 Mac 上记录。**没有“停止记录”开关，“显示文本历史”只决定入口是否显示。

在“设置 → 文本”中可以：

- 打开历史查看和复制正文，删除单条，或确认后清空全部。
- 隐藏时选择“保留并隐藏”“清空并隐藏”或取消。
- 选择“最近 500 条”（默认，发送接收合计）、“最近 30 天”或“一直保留”。缩短保留范围会在确认后删除超出范围的旧记录。
- 在历史入口隐藏时仍可清空。之后新的成功收发仍会记录。

历史仅保存在本机，不是共享或加密归档。本机删除不会删除对方副本，也不保证安全擦除。通知对应记录已删除或过期时，打开会显示说明。

保存历史失败时，可用文本暂存在本次运行的内存中，仍可复制，应用明确提示未保存历史。重要内容请在退出前另行保存，详见[文本说明](TEXT.md)。

## 日常设置——0.4.0

| 页面 | 主要用途 |
|---|---|
| 通用 | 本机名称、语言、菜单栏／Dock 图标、登录启动、启动连接及动画总开关 |
| 设备 | 默认目标、连接、配对／解除配对及手动连接信息 |
| 传输 | 接收目录、自动打开、发送文件及最近收件 |
| 文本 | 发送／查看文本、历史显示、保留方式及清空 |
| 关于 | 产品版本、检查更新、诊断详情及维护 |

名称修改需点击“保存”，开关立即保存。语言选择在退出重开后生效，先完成传输；系统文件选择器、权限提示及部分系统错误可能沿用 macOS 语言。动画使用固定节奏，可通过总开关或系统“减少动态效果”关闭。

### 图标开关

“显示菜单栏图标”和“显示 Dock 图标”独立，可都开、只开一个或都关。隐藏图标不退出应用、不停止传输。

都隐藏时，手动重新打开应用会临时恢复菜单栏并打开设置，保存的菜单栏选择仍为关闭。开启该开关才会永久显示；也可点击“隐藏临时图标”再隐藏。登录启动尊重已保存的隐藏选择。

不显示 Dock 图标时，切换到其他应用，设置窗口可能自动隐藏。从菜单或 Applications 重开即可恢复页面和未保存名称。真正退出请使用菜单“退出”。

## 手动连接、解除配对与换设备

仅在自动发现失败时使用手动连接：

1. 在目标 Mac 展开“设备 → 手动连接信息”。
2. 获取当前启用的 Wi-Fi／以太网地址和监听端口。
3. 在另一台选择“手动地址…”，输入**目标电脑**的地址与端口。新设备仍需两端开启“添加设备”并核对验证码。

“其他网络地址”列出 VPN、虚拟或隧道接口，不保证所有地址都可达。重启后端口可能变化，应使用当前值；这一局域网工作流不需要把端口转发或开放到互联网。

“解除配对…”删除信任，而不只是关闭当前连接。本机立即停止相关任务；两端支持且有认证连接时，同步确认表示对方也已保存撤销结果。对方离线、版本较旧或无法确认时，提示“本机已解除，对方尚未确认”，不能认为对方记录也已修改。再次使用需双方开启“添加设备”并核对新验证码；普通退出和断网不会解除配对。

换电脑时在新机正常安装并重新配对，在保留的设备上解除旧设备。不要复制旧机钥匙串身份或配置。“重置身份”会要求重新配对，是维护操作，不是日常重连的首选修复。

## 更新与排查

点击“检查更新…”查询 GitHub 上更新的正式版本，检查为手动触发，只增加本地构建号不会提示公开更新。0.4.0 开发版可能显示领先于公开的 0.3.2，这是正常现象，不是在建议降级。

更新时先完成传输，点击“退出”，使用新 DMG 替换已安装 App，再重新打开。正常更新保留配置和配对；从 OpenOnMini 迁移前先退出旧 App，避免两个同时运行。详见[更新说明](UPDATES.md)。

| 现象 | 检查方法 |
|---|---|
| 看不到设备 | 两端应用运行、电脑唤醒、同一局域网、局域网权限、访客 Wi-Fi／设备隔离；再尝试手动地址 |
| 已配对但未连接 | 打开对方应用，在设备页连接或重新发送文件；通常不需要重置配对 |
| 提示不支持文本 | 两端都需要支持文本，公开 0.3.2 安装包不包含此功能 |
| 没有通知 | 检查通知权限；查看接收目录，或文本页最近收件入口 |
| 无法保存／空间不足 | 检查接收端目录权限与剩余空间，打开设置查看完整错误 |
| 出现钥匙串授权 | 核对 App 来源及固定 Applications 路径；重编译／签名变化可能再次请求授权，不要首先删除身份 |
| 错误文字显示不全 | 在设置点击“查看详情…”阅读完整信息 |

反馈请提供“关于 → 诊断详情”中的版本／构建号、macOS 版本和复现步骤。截图移除私人路径、文件名、设备标识和文本；不要附配置、私钥或历史数据库。[Issues](https://github.com/TimeLyr1c/PeerJetty/issues) · [安全反馈](../SECURITY.md)。

## 文件与数据在哪里

| 内容 | 位置／归属 |
|---|---|
| 已安装应用 | `/Applications/PeerJetty.app` |
| 收到的文件 | 本机选择的接收目录，属于普通用户文件 |
| 设置与信任 | `~/Library/Application Support/PeerJetty/` |
| 私有设备身份 | 本机钥匙串 |
| 文本历史 | `~/Library/Application Support/PeerJetty/TextHistory/history.sqlite` |
| 源码与本地构建 | 自己的源码目录；本地构建在 `outputs/`，与应用数据分开 |

私有运行数据不进入 Git、Dropbox 或反馈附件。PeerJetty 只传送选中的内容，不镜像文件夹、不后台同步历史、不保证全部 macOS 元数据保真，也不代替备份。实现边界见[协议](PROTOCOL.md)，源码管理见[开发工作流](WORKFLOW.md)。
