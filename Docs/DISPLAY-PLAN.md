# 上方中央投放入口：0.2.6 / build8

## 实现与设计

0.2.4 检测到文件拖拽就展开黑色面板，并优先选择有刘海的屏幕。无刘海屏幕用 visibleFrame 顶部定位，黑框会停在菜单栏下方；有刘海时直接把窄黑框接在刘海下方，也容易与并列窗口的圆角形成不自然的缺口。

0.2.5 改用顶边触发的独立卡片，但用户实测仍会与 macOS 调度中心冲突。0.2.6 将触发区域下移，默认隐藏，只在有效文件拖到菜单栏下方、所在屏幕上方中央的接近区时出现。它不尝试填平其他应用的窗口圆角，也不需要读取别的应用窗口或申请辅助功能权限。卡片位于菜单栏／刘海安全区域下方，至少留 12 点间距，且距物理顶边至少 64 点；76 点高，至少 320 点宽，较宽刘海相应增加宽度并限制在屏幕内。四角圆润、原生 HUD 材质与阴影让它表现为临时投放工具，不模拟新增的硬件刘海。

两类屏幕均使用菜单栏下方的接近区；有刘海屏幕用 safeAreaInsets.top 和 auxiliaryTopLeftArea / auxiliaryTopRightArea 之间的间隙识别位置及宽度，刘海用于确定水平居中位置和安全区域，不把刘海或物理顶边作为触发区。不按机型名称或固定像素猜测，不把任意非零安全区域直接当成可测量的刘海。辅助区域缺失或异常时，回退到屏幕中央，同时仍避开顶部安全区域。

接近区为卡片本身加左右各 24 点、下方 48 点，上方不延伸到菜单栏；从下往上拖时，先进入接近区再进入卡片。触发屏幕由鼠标进入哪块屏幕的接近区决定。文件触发时直接在最终位置显示卡片，不从屏幕顶边滑下，也不要求停留等待；预览和状态提示仍可淡入淡出。接近区和卡片组成连续保留区域，离开后有 0.25 秒缓冲，返回即撤销收起。跨屏拖到另一个接近区可切换；忙于文件承诺／传输时保持所在屏幕和状态。拖拽结束／取消后收起，进度及错误原有短暂展示规则保留。预览仍显示 5 秒；减少动态效果开启时不执行淡入淡出动画。

显示器重连重新定位，菜单栏显隐变化时重新计算卡片位置。坐标使用屏幕全局点坐标，并按 backingScaleFactor 对齐；不会默认选择 Air 而忽略外接屏。

## 检查与验收

自动检查使用 Scripts/test-drop-presentation.sh，不依赖 XCTest 或完整 Xcode，不启动生产 App、传输引擎、钥匙串或配置。覆盖无刘海的菜单栏下方提前触发、模拟向上路径先进入接近区、物理顶边排除、180/220/300 点刘海、保留区域、负屏幕坐标、自动隐藏菜单栏、无效辅助区域、旧拖拽剪贴板和文本误触发，以及卡片控件布局与完整圆角裁切。

以下仍需实体设备手工验收，不能由模拟几何或离屏视图快照代替：

1. mini 普通显示器上：未拖拽／在普通窗口拖动／拖文字均无卡片；文件到菜单栏下方、上方中央提前出现卡片，再进入卡片松开发送，离开和取消可收起。
2. Air：系统缩放改变后入口仍水平对齐刘海且避开菜单栏；卡片内容不进入刘海，左右分屏时表现为完整独立圆角卡片。
3. 外接屏：两块屏幕分别触发，不总跳回 Air；横向／纵向布局、负坐标、不同缩放及热插拔。
4. 原生全屏、Split View、普通并列窗口、多个 Space、菜单栏自动隐藏；验证能接收拖拽且不抢键盘焦点。
5. 文件承诺、取消、传输进度、完成／错误提示、设置预览，以及后续普通鼠标拖动不误触发。

不会关闭、拦截或修改 macOS 调度中心／窗口管理手势。新操作路径不需要到顶边，但用户继续拖进真实顶边／菜单栏时仍可能触发系统行为；避免冲突的实际效果需 mini 与 Air 复测。系统全屏与不同 Space 下的实际投放事件派发需实机验证；本实现不保证覆盖所有窗口管理软件或显示器配置。

参考：[Apple safeAreaInsets](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets)、[auxiliaryTopLeftArea](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytopleftarea-uglc)、[auxiliaryTopRightArea](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytoprightarea-gr2n)。
