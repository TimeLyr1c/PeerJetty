# 顶部投放入口：0.2.5 / build7

## 实现与设计

0.2.4 检测到文件拖拽就展开黑色面板，并优先选择有刘海的屏幕。无刘海屏幕用 visibleFrame 顶部定位，黑框会停在菜单栏下方；有刘海时直接把窄黑框接在刘海下方，也容易与并列窗口的圆角形成不自然的缺口。

0.2.5 改用独立圆角投放卡片，默认隐藏，只在有效文件拖到所在屏幕顶部中央时展开。它不尝试填平其他应用的窗口圆角，也不需要读取别的应用窗口或申请辅助功能权限。展开后位于菜单栏／刘海安全区域下方，保留 8 点间距；76 点高，至少 320 点宽，较宽刘海相应增加宽度并限制在屏幕内。四角圆润、原生 HUD 材质与阴影让它表现为临时投放工具，不模拟新增的硬件刘海。

无刘海屏幕的入口在真正的屏幕顶边中央；有刘海屏幕用 safeAreaInsets.top 和 auxiliaryTopLeftArea / auxiliaryTopRightArea 之间的间隙识别位置及宽度，入口也覆盖刘海下方可访问的区域。不按机型名称或固定像素猜测，不把任意非零安全区域直接当成可测量的刘海。辅助区域缺失或异常时，回退到屏幕中央，同时仍避开顶部安全区域。

触发屏幕由鼠标进入哪块屏幕的顶部入口决定。进入投放区后，顶边、菜单栏间距和卡片组成连续保留区域，避免下降途中收起；离开后有 0.25 秒缓冲，返回即撤销收起。跨屏拖到另一个顶部入口可切换；忙于文件承诺／传输时保持所在屏幕和状态。拖拽结束／取消后收起，进度及错误原有短暂展示规则保留。预览仍显示 5 秒；减少动态效果开启时不执行滑动动画。

显示器重连重新定位，菜单栏显隐变化时重新计算卡片位置。坐标使用屏幕全局点坐标，并按 backingScaleFactor 对齐；不会默认选择 Air 而忽略外接屏。

## 检查与验收

自动检查使用 Scripts/test-drop-presentation.sh，不依赖 XCTest 或完整 Xcode，不启动生产 App、传输引擎、钥匙串或配置。覆盖无刘海顶边触发、180/220/300 点刘海、保留区域、负屏幕坐标、自动隐藏菜单栏、无效辅助区域、旧拖拽剪贴板和文本误触发，以及卡片控件布局与完整圆角裁切。

以下仍需实体设备手工验收，不能由模拟几何或离屏视图快照代替：

1. mini 普通显示器上：未拖拽／在普通窗口拖动／拖文字均无卡片；文件到顶部中央才展开，下降进卡片后可松开发送，离开和取消可收起。
2. Air：系统缩放改变后入口仍对齐刘海；卡片内容不进入刘海，左右分屏时表现为完整独立圆角卡片。
3. 外接屏：两块屏幕分别触发，不总跳回 Air；横向／纵向布局、负坐标、不同缩放及热插拔。
4. 原生全屏、Split View、普通并列窗口、多个 Space、菜单栏自动隐藏；验证能接收拖拽且不抢键盘焦点。
5. 文件承诺、取消、传输进度、完成／错误提示、设置预览，以及后续普通鼠标拖动不误触发。

系统全屏与不同 Space 下的实际投放事件派发需实机验证；本实现不保证覆盖所有窗口管理软件或显示器配置。

参考：[Apple safeAreaInsets](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets)、[auxiliaryTopLeftArea](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytopleftarea-uglc)、[auxiliaryTopRightArea](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytoprightarea-gr2n)。
