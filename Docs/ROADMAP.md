## 2. 多语言支持（i18n）

internationalization 缩写为 i18n：i 与 n 之间有 18 个字母。它表示让程序具备适应多种语言/地区的结构；具体翻译与地区适配称为 localization（本地化，l10n）。

- [ ] 第一阶段：简体中文和英文，默认跟随系统语言。
- [ ] 抽离窗口、菜单、按钮、通知、进度、错误、首次设置与配对提示中的固定文字。
- [ ] 使用稳定的文字键和可翻译资源；不通过拼接片段构造句子。
- [ ] 将系统权限说明也本地化；构建脚本正确复制 .lproj 等资源。
- [ ] 当前采用 SwiftPM 加脚本组装 App，先选择适配此流程的资源方案，不要求为了翻译迁到完整 Xcode 工程。
- [ ] 处理复数、数量、文件大小、日期与长文字布局；缺少翻译时有默认语言回退。
- [ ] 显示语言不改变协议字段、设备身份、文件名或用户填写的设备名称。
- [ ] 中文/英文两台设备仍能互相配对和传输；全部系统授权和错误路径可理解。
- [ ] 按实际需求再增加手动语言选择；公开翻译贡献方法。

## 3. 日常双机体验与需求验证

- [ ] 让首次安装、配对和选默认目标更易理解。
- [ ] 针对固定两台 Mac 的高频传输做对比试用，记录准备时间、首次设置、完成耗时、失败与恢复情况。
- [ ] 检查目标设备变化/离线时的反馈，防止用户误以为已经送达。
- [ ] 持续验证 Finder/微信拖拽、睡眠恢复、网络变化和同名文件。
- [ ] 可考虑固定目标快捷键、清晰的接收目录管理；是否实现由试用结果决定。

不以未经测试的“比 AirDrop 更快、更安全、更稳定”为宣传。屏幕顶部/刘海投放入口已有类似产品，真正需要验证的是固定工作设备之间的持续交接价值。

## 4. 应用内更新

- [ ] 先实现检查版本、展示变化和引导下载。
- [ ] 自动安装阶段评估成熟更新框架；独立验证更新签名、失败恢复和回滚。
- [ ] 稳定/测试渠道分别管理；保留设备配对和配置。
- [ ] 明确本地签名、Developer ID、公证与实际更新方式的关系。

本次版本和打包工具不等于应用内自动更新功能。
